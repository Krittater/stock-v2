เอกสารนี้อธิบายหน้า "เบิกของ" ที่ ใช้งานจริงใน mock ตอนนี้ (ฉบับ 8 พ.ย. 2569 หลัง IF49) เพื่อให้ designer ออกแบบหน้าจอใหม่ ได้ โดยรู้ว่าผู้ ใช้ต้องทำอะไร เห็นอะไร และระบบต้องแจ้งอะไรเมื่อไร designer
เริ่มที่หัวข้อ 0 (สิ่ งที่ต้องส่ ง ข้อกำหนด สี ฟอนต์ ข้อมูลตัวอย่าง และภาพหน้าจอปั จจุบัน)
สรุป 5 บรรทัด

     หน้านี้ ให้ผู้ ใช้ "เบิกของออกจากคลังไปใช้กับงาน" ให้จบในหน้าเดียว ใช้เวลาไม่กี่ครั้งแตะ ทั้งบนมือถือหน้างานและบนคอม
     ลำดับตายตัว 3 ขั้น: 1 เลือกของ+จำนวน → 2 เลือกคลัง → 3 เลือกงาน แล้วกด "เบิกเลย" ขั้นถัดไปเปิ ดเมื่อขั้นก่อนครบ ขั้นที่ยังไม่ถึงโชว์เป็ นแถบล็อกบอกว่าต้องทำอะไรก่อน
     ของที่มีสเปกเยอะ (สายไฟ) ใช้ "ชิปกรอง" ชนิด/ขนาด/แกน/สี แทนการอ่านชื่อยาว ๆ
     ตัวเลขทุกตัวต้องมีคำกำกับ (ขอเบิก / มี ในคลังนี้ / ขาด) และตัวเลขแต่ละชนิดโผล่ที่เดียว (กฎ IF48)
     มีข้อความแจ้งเตือนในหน้านี้และที่ส่ งถึงคนอื่นรวม 75 รายการ (หัวข้อ 5) ทุกข้อมีข้อความปั จจุบัน และบางข้อมีข้อเสนอแก้ถ้าข้อความเดิมไม่ชัดหรือขาด

    1. ช่องค้นหา ข้อความช่วย "ค้นหาของ ชื่อ ยี่ห้อ รหัส" ค้นได้จาก: ชื่อ, ยี่ห้อ, รุ่น/ขนาด, รหัสสิ นค้า, รหัสจากผู้ขาย/บาร์ โค้ด ผลลัพธ์ขึ้นใต้ช่องทันที ไม่ ใช้เมนูลอย (ใช้ง่ายบนมือถือ)
    2. ใช้บ่อย ปุ่ มของ 4 ชิ้นล่าสุ ดที่ผู้ ใช้คนนี้เคยเบิก แตะ = เพิ่มเข้ารายการเลย ถ้าผู้ ใช้ยังไม่เคยเบิก ส่ วนนี้ ไม่แสดง
    3. หมวด ปุ่ มชิป "ทั้งหมด" + แต่ละหมวดที่มีสิ นค้า (สายไฟ สายสื่ อสาร ท่อและราง อุปกรณ์ ไฟฟ้ า วัสดุสิ้ นเปลือง ฯลฯ) เลือกได้ทีละหมวด แตะซ้ำ = ยกเลิก ถ้ามีหมวดเดียวไม่แสดง แถวชิปตัดขึ้นบรรทัดใหม่ ไม่
    ให้ เลื่ อนแนวนอน
    4. ชิปสเปกสายไฟ (ดูหัวข้อถัดไป)
    5. ล้างตัวกรอง ลิงก์ ปรากฏเมื่อเลือกหมวดหรือชิปสเปกอยู่ (ไม่ล้างคำค้น)
    6. ผลลัพธ์ การ์ดละ 1 สิ นค้า (ดูด้านล่าง) สู งสุ ด 8 ใบ มีปุ่ ม "แสดงเพิ่ม (อีก N)" ถ้ามีมากกว่านั้น
    7. สร้างสิ นค้าใหม่ แถวเส้ นประท้ายผลลัพธ์ "สร้างสิ นค้าใหม่ "{คำที่พิมพ์}"" ขึ้นเมื่อพิมพ์ค้นหาและไม่มีสิ นค้าชื่อตรงกันทุกตัวอักษร (ดูหัวข้อสร้างสิ นค้าใหม่)

รายการที่จะเบิก (หัว "รายการที่จะเบิก (N รายการ)" มีดาวแดงบังคับ):

     แถวเล็ก 1 แถวต่อ 1 ของ แถวสลับสี พื้น ไม่มีเส้ นขอบ ไม่มีเลขลำดับ ไม่มีปุ่ ม +/− (กว้างไม่พอที่ 390px)
     ซ้าย: ชื่อสิ นค้า (ตัวหนา) + ยี่ห้อ · รุ่น (เทา) · ขวา: ป้ าย "ขอเบิก" + ช่องจำนวนพร้อมหน่วยท้ายช่อง (เช่น "25 ตัว", "80 m") + ปุ่ ม ✕ ลบ (เอา "ชื่อ" ออก) ที่ 390px ป้ ายและช่องจำนวนลงบรรทัดใต้ชื่อ
     ไม่แสดงตัวเลขสต็อกที่ขั้นนี้เด็ดขาด (มี/ขาด อยู่ที่ขั้น 2 เท่านั้น IF48)
     เพิ่มของแล้วเคอร์เซอร์ ไปอยู่ช่องจำนวนทันที (มือถือ: แป้ นตัวเลข) กด Enter ในช่องจำนวน = ไปที่ปุ่ มเบิก/ช่องงานที่ยังขาด
     จำนวน: ต้องมากกว่า 0 ทศนิยมได้สู งสุ ด 2 ตำแหน่ง (ปั จจุบันทุกหน่วย ดูข้อเสนอ N07) ไม่มีเพดานสู งสุ ดที่ขั้นนี้ จำนวนเกินที่มี ในคลังไม่ ใช่ error แต่เป็ น "ขาด" ที่ขั้น 2
     หน่วย: แสดงหน่วยของสิ นค้านั้น (ตัว กล่อง ถุง เส้ น ใบ m ฯลฯ) ผู้ ใช้ ไม่เลือกหน่วยเอง สายม้วนเป็ นเมตร (m) เสมอ
     ลบรายการ: ปุ่ ม ✕ ลบทันที ไม่ถามยืนยัน ถ้าลบจนไม่เหลือรายการ ขั้น 2–3 หายและตัวหาของกลับมาเปิ ด
     ซ้ำ: เพิ่มของที่มีอยู่แล้ว → ไม่เพิ่มแถวใหม่ (N05)

    สต็อก" (เหลือง และกดเลือกไม่ ได้) ช่องที่เลือกแล้วโชว์ชื่อ + ผลสั้ นเช่นกัน
    2. ลำดับคลัง: คลังที่ ไม่ล็อกก่อน → คลังที่ครบก่อน → ครบเมื่อรวมยอดรอยืนยัน → สั ดส่ วนที่ครอบคลุมมากกว่า → ชื่อ
    3. "แนะนำ" = คลังแรกที่มีของครบตอนนี้ ถ้าไม่มีคลังไหนครบ ใช้คลังแรกที่จะครบเมื่อยอดตั้งต้นที่รอยืนยันถูกยืนยัน
    4. เลือกอัตโนมัติ: ทำเฉพาะตอนยังไม่มีคลังที่เลือก และ (ก) มีคลังเดียวที่ ใช้ ได้ หรือ (ข) มีคลังเดียวที่ครบ หรือ (ค) ไม่มีคลังครบแต่มีคลังเดียวที่ครบเมื่อรวมยอดรอยืนยัน · ผู้ ใช้เปลี่ยนได้เสมอ · ไม่ทับคลังที่ผู้
    ใช้เลือกเอง · การเลือกอัตโนมัติ ไม่ย้ายเคอร์เซอร์ (ผู้ ใช้อาจกำลังพิมพ์จำนวน) ส่ วนเลือกเองแล้วเคอร์เซอร์ ไปช่องงาน
    5. มีคลังเดียว: ไม่มี dropdown แสดง "เบิกจาก {ชื่อคลัง}" + ตาราง
    6. ยังไม่เลือก: ข้อความ "เลือกคลังเพื่อดูว่ามีของพอไหม" (N26) ถ้าไม่มีของในคลังไหนเลย: ข้อความ N25 เหนือ dropdown
    7. ตารางรายละเอียดของคลังที่เลือก (เฉพาะคลังที่เลือกอยู่ ไม่มีกรอบซ้อน): คอลัมน์ ของ | ขอเบิก | มี ในคลังนี้ | ผล

8. ข้อกำหนดการออกแบบ (constraint)

     กว้าง 390px ต้องใช้ ได้ ไม่มีแถบเลื่อนแนวนอนของทั้งหน้า (ชิปขึ้นบรรทัดใหม่ ตารางเรียงซ้อนเป็ นแถว ชื่อยาวตัดบรรทัดไม่ตัดด้วย "…" ยกเว้นรายการงานใน dropdown)
     จุดแตะ ≥ 44px ทุกปุ่ ม ชิป ช่องกรอก ลิงก์ที่กดได้ (ปุ่ มเบิกสู ง ≥ 48px)
     ตัวอักษร ≥ 14px (ข้อความรอง/ป้ ายเล็กต่ำสุ ด 14px เนื้อหาหลัก 16px หัวขั้น 18px)
     dark mode: ต้องรองรับ ทุกสี สถานะ (เขียว เหลือง แดง ฟ้ า) อ่านชัดทั้งสองโหมด
     ฟอร์มเต็มความกว้าง (IF47) ในแท็บ "เบิกของ" ไม่มีตารางหรือประวัติปนในหน้าเดียวกัน (ประวัติอยู่แท็บ "ใบเบิกที่ผ่านมา")
     ใช้ component PrimeVue 4 + Tailwind ของโปรเจกต์: ปุ่ ม (Button) ช่องข้อความ (InputText) ช่องตัวเลข (InputNumber) Select (dropdown คลัง) AutoComplete (ค้นงาน) Dialog (สร้างสิ นค้า/
     งาน) Message (กล่องแดง/เหลือง) ToggleSwitch Checkbox Tabs Toast ไม่ ใช้ UI library อื่น สี หลักและฟอนต์เป็ นของแอปเดิม (โทนเขียว)
     อนิเมชัน: ขั้นกางลง 200 มิลลิวินาที ปิ ดเมื่อผู้ ใช้ตั้งลดการเคลื่อนไหว

9. Acceptance criteria (Given / When / Then)

ขั้น 1 · เลือกของ

     IP-AC1 Given เปิ ดหน้า "เบิกของ" ใหม่ · When ยังไม่เลือกอะไร · Then เห็นหัวขั้น 1 ช่องค้นหา (ข้อความช่วยตามข้อ 3) ใช้บ่อย (ถ้ามีประวัติ) หมวด และแถบล็อก 3 แถบ (N08–N10) ไม่เห็นขั้น 2–3
     IP-AC2 Given ผู้ ใช้พิมพ์ชื่อ ยี่ห้อ รุ่น หรือรหัสผู้ขายบางส่ วน · When ผลลัพธ์ขึ้น · Then การ์ดมีชื่อ ยี่ห้อ·รุ่น และ "มีทั้งหมด …" หรือ "ไม่มีของ" เรียงตามกติกาข้อ 3 สู งสุ ด 8 ใบ และมี "แสดงเพิ่ม (อีก N)"
     ถ้ าเกิ น
     IP-AC3 Given ค้นหาไม่ตรงสิ นค้าใด · When ผลลัพธ์ว่าง · Then เห็น "ไม่พบสิ นค้า" และแถว "สร้างสิ นค้าใหม่ "{คำค้น}"" (ไม่เห็นแถวสร้างถ้าชื่อซ้ำทุกตัวอักษร)
     IP-AC4 Given ผลลัพธ์มีสายไฟและผู้ ใช้เลือกหมวด "สายไฟ" · When ดูตัวกรอง · Then เห็นแถวชิป ชนิด/ขนาด (sq.mm)/แกน/สี เฉพาะแถวที่มีค่ามากกว่า 1 ค่า แต่ละชิปมีตัวเลขจำนวนสิ นค้า
     IP-AC5 Given เลือกชิป "THW" · When ดูแถวขนาดและสี · Then เหลือเฉพาะค่าที่ THW มี ผลลัพธ์เหลือเฉพาะ THW ชิป THW เป็ นสี หลักอ่านชัด แตะซ้ำแล้วกลับเป็ นไม่เลือก
     IP-AC6 Given เลือกชิปหลายแถว (เช่น THW + 2.5 + ดำ) · When ดูผลลัพธ์ · Then มีเฉพาะสิ นค้าที่ตรงทุกชิป และมีลิงก์ "ล้างตัวกรอง" ที่ล้างหมวดและชิปทั้งหมดแต่ ไม่ล้างคำค้น
     IP-AC7 Given ผู้ ใช้ยังไม่เลือกหมวด ไม่พิมพ์อะไร ไม่เลือกชิป · When เปิ ดหน้า · Then ไม่เห็นแถวชิปสเปก (หน้าแรกสั้ น)
     IP-AC8 Given แตะการ์ดสิ นค้า · When เพิ่มสำเร็จ · Then เกิดแถวในรายการ "รายการที่จะเบิก (1 รายการ)" เคอร์เซอร์อยู่ที่ช่องจำนวนของแถวนั้น ตัวหาของพับเหลือปุ่ ม "เพิ่มของ" การ์ดนั้นแสดง "เพิ่ม
     แล้ ว"
     IP-AC9 Given สิ นค้านั้นเพิ่มไปแล้ว · When แตะการ์ดซ้ำ · Then ไม่เกิดแถวใหม่ จอเลื่อนไปแถวเดิม เห็นกล่องเหลือง N05 ประมาณ 6 วินาที (หายเมื่อแก้จำนวน)
     IP-AC10 Given มีรายการ 3 ชิ้น · When ดูแถว · Then แต่ละแถวมีป้ าย "ขอเบิก" ช่องจำนวนพร้อมหน่วย ปุ่ ม ✕ ≥ 44px และ ไม่มี ตัวเลขมี/ขาดในขั้นนี้

10. นอกขอบเขต · คำถามเปิ ด · สิ่งที่ โค้ดกับเอกสารไม่ตรงกัน

นอกขอบเขต: แท็บ "ใบเบิกที่ผ่านมา" และ "คืนของ" (มีแค่แถบแท็บ) · หน้าหยิบของ หน้าอนุมัติ หน้ารับของ/รายการต้องซื้อ · การนับสต็อก · โหมดเต็มรูปแบบ (ฟอร์มเบิกเดิมไม่เปลี่ยน) · ยอดตั้งต้นที่ต้องการให้
เลือกชั้น (ตอนนี้วางที่ "ทั่วไป" เสมอ) · การสแกน QR/บาร์ โค้ด · รองรับออฟไลน์ · รูปสิ นค้า
คำถามเปิ ด
รอผู้บริหาร (แตะขั้นตอนสั่ งซื้อ = ต้องอนุมัติ)

    1. ของใหม่ที่ยังไม่เคยมีในคลัง ให้ Store ตรวจก่อนส่งบัญชีซื้อไหม ตัวเลือก: ก (แนะนำ) Store ตรวจก่อน ว่ามีของอยู่จริงไหม แล้วค่อยส่ งบัญชี · ข แจ้ง Store และบัญชีพร้อมกัน · ค แบบเดิม ส่ งบัญชีเลย ·
    ผลต่อหน้านี้: ข้อความ N59/N41 จะเปลี่ยน ("ระบบจะสร้างรายการต้องซื้อ" → "Store ตรวจก่อน แล้วจึงส่ งให้บัญชี") และผู้เบิกต้องรอ ตอนนี้ ใช้แบบ ค (IF36)
    2. Store ตอบ "ไม่มีของ" (ปฏิเสธยอดที่วิศวกรแจ้ง) แล้ว ระบบควรสร้างรายการต้องซื้อให้ ใบเบิกที่รออยู่อัตโนมัติไหม ตอนนี้ ไม่สร้าง (IF20/IF25) ใบเบิกยังค้าง "รอของ" โดยไม่มี ใครได้แจ้งให้ซื้อ (ตาม
    โค้ด ต้องให้ tester ยืนยันบน UI) · คำแนะนำ: ให้สร้างอัตโนมัติ ตอน Store กด "ไม่มีของ" และแจ้งผู้เบิกด้วย N73 · แตะขั้นตอนสั่ งซื้อ

BA ตัดสิ นใจเองเป็ นสมมติฐาน (บอกเหตุผล แก้ ได้ถ้าไม่เห็นด้วย)
    3. แจ้งเตือน "ใบขอซื้อใหม่" ถึงใคร — ตอนนี้ถึงทุกคนที่มีสิ ทธิ์ดูของขาด ในโหมดเล็กคือ ทุกบทบาท รวมผู้เบิกเอง (N68) สมมติฐาน: ควรส่ งเฉพาะบัญชี Store หัวหน้า เพราะวิศวกรไม่ ได้เป็ นผู้ซื้อและจะถูก
    แจ้ งเตื อนเยอะเกิ นไป
    4. แจ้งผู้เบิกว่าจ่ายของแล้ว (N69) ตอนกดเบิกเลยเอง — สมมติฐาน: ไม่ควรแจ้ง เพราะการ์ดผลบอกอยู่แล้ว แจ้งเฉพาะตอนคนอื่นเป็ นคนจ่ายให้
    5. แจ้งเตือนที่ไม่มีลิงก์ (N66, N67, N69, N70, N72, N73) — สมมติฐาน: ควรมีลิงก์ ไปหน้าหยิบ/ใบเบิกที่เกี่ยวข้อง โดยเฉพาะ N66 ที่การ์ด N61 สั ญญาไว้ว่า "แล้วกดไปจ่ายของได้เลย"
    6. ออฟไลน์ — ต้องรองรับในหน้านี้ ไหม (หน้างานบางที่สั ญญาณไม่ดี) ตอนนี้ ไม่รองรับ สมมติฐาน: นอกขอบเขตรอบนี้ ให้ designer เผื่อพื้นที่แถบสถานะการเชื่อมต่อไว้เท่านั้น
    7. จำนวนทศนิยมของของที่นับเป็ นชิ้น (N07) — สมมติฐาน: หน่วยที่ ไม่ ใช่เมตรรับจำนวนเต็มเท่านั้น (ต้องแก้ระบบเล็กน้อย)
    8. การ์ดผลใช้ขอบซ้ายสี — ผู้บริหารยังไม่ตัดสิ นว่าจะเปลี่ยนเป็ นไอคอน+ป้ ายตัวอักษรไหม สมมติฐาน: ให้ designer ออกแบบให้อ่านผลได้ โดยไม่พึ่งสี อย่างเดียว (ตรงกับข้อ 4 และ 8)
